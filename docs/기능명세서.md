제안서 `에이전트_탐지_역추적_통합제안서.md`의 핵심을 실제로 돌아가는 최소 구현으로

탐지·차단·추적이 동작합니다.

## 2. 기능별 명세

### F1. 실행 전 관문 (탐지·차단) — `Monitor.guard_action`

- **입력:** `session, agent, action, content`. `action ∈ {exec, write, send, autorun}`.
- **처리:** `policy.yaml` 규칙을 위에서부터 평가, 첫 매칭 채택. 매칭 없으면 `allow`.
- **출력:** `(verdict, reason)`, `verdict ∈ {allow, ask, block}`. 판정은 `verdict`
  이벤트로 저장소에 기록됨.
- **기본 내장 규칙:** EICAR 테스트 문자열(block), 인코딩 PowerShell(block),
  원격 코드 실행 `iex/invoke-expression/downloadstring/certutil/파이프 셸`(block),
  자격증명 접근 `mimikatz/lsass/.aws·.ssh/id_rsa`(ask), 자동 실행 등록(ask),
  외부 전송(기본 allow, 오염 시 격상).

### F2. 오염 추적 기반 권한 축소 — `Monitor.record_read` + `tainted_escalate`

- 외부(`from_internet=True`) 또는 이미 감염된 artifact를 읽은 **세션은 오염** 상태가 됨.
- 오염 세션에서 `tainted_escalate` 목록(`exec/send/autorun/write`)의 행동은
  `allow/ask` 판정이 **`ask`로 격상**. `block`은 그대로 block.

### F3. 복제 탐지 — `Monitor._detect_replication`

세 조건을 **모두** 만족할 때만 복제로 판정(제안서 §5.4):

1. **유사도** `similarity ≥ 0.80` — 같은 세션에서 앞서 읽은 콘텐츠와 비교(`difflib`).
2. **지시문 점수** `directive_score ≥ 0.16` — 명령형 + "복사·전달·포함하라",
   가짜 시스템 문구 등 정규식 규칙(ko/en) 중 1개 이상 매칭.
3. **직후 고위험 행동** `next_action ∈ {send, exec, autorun, persist, write}`.

→ 정상 답장·인용은 2번(지시문)이 0이라 걸러짐(오탐 방지, 테스트로 검증).
복제로 판정되면 복제본 artifact를 `infected`로 표시하고 `replication` 간선과
사건(incident)을 기록.

### F4. 역추적 — `trace.analyze`

- `replication` 테이블을 `networkx` 유향 그래프(`src → replica`)로 올림.
- **최초 감염원(역방향):** 감염 artifact의 조상 중 인터넷 유입 표시가 있고,
  그 자신은 인터넷 조상이 없는 **가장 이른 노드**.
- **감염 범위(순방향):** 감염원의 모든 후손 = 정리 대상 목록.
- **출력:** `{origin, scope, edges}` — 간선마다 유사도 신뢰도 포함.

### F5. 우회·조작 탐지 — `store` 교차 검증 + `verify_chain`

- 관문을 거치지 않은 OS 변경(`os_event`)과 에이전트 보고(`verdict`)를 대조해
  **불일치**를 드러냄(S5).
- 모든 이벤트는 **해시 체인**(각 레코드가 이전 레코드 해시를 포함). 에이전트가
  과거 기록을 고치면 `verify_chain()`이 **첫 변조 레코드 번호**를 반환.

### F6. 근거 기반 설명 — `report.incident_report`

4단 구조: **관찰 사실 / 가능한 해석 / 판단 한계 / 사용자 조치**. 규칙 기반 템플릿이라
오프라인 동작. LLM은 이 사실을 읽기 좋게 바꾸는 용도로만 교체 가능.

## 3. 데이터 모델 (`store.py`, 제안서 §5.3)

| 테이블 | 핵심 컬럼 | 용도 |
|---|---|---|
| `event` | id, ts, kind, session, agent, data(JSON), **prev_hash, hash** | 변조 방지 append-only 로그(단일 원천) |
| `artifact` | id(=sha256), kind, location, from_internet, tainted, infected | 콘텐츠 상태 |
| `replication` | src, replica, similarity, directive, next_action | 전파 간선 |
| `incident` | rule, evidence, source, scope, status | 사건 + 역추적 결과 |

`event`가 단일 원천이고 나머지는 거기서 파생되는 인덱스입니다. `kind ∈
{read, write, action, verdict, os_event, incident}`.

## 4. 판정 임계값 (`engine.py` 상단, 조정 가능)

| 상수 | 기본값 | 의미 |
|---|---|---|
| `SIM_THRESHOLD` | 0.80 | 복제로 볼 최소 유사도 |
| `DIRECTIVE_THRESHOLD` | 0.16 | 복제로 볼 최소 지시문 점수(≈ 패턴 1개) |
| `HIGH_RISK` | send/exec/autorun/persist/write | 복제의 "직후 고위험 행동" |

제안서 §9의 **"복제 판정 기준값 결정"**은 이 상수로 노출됩니다. 평가 데이터로 튜닝하세요.

## 5. 보안 설계 (제안서 §5.5)

- 저장소는 append-only 해시 체인 → 사용자 권한 에이전트가 과거 기록 변조 불가(탐지됨).
- 판정 로직에 **원문을 그대로 넣지 않고** 특징값(지문·점수)만 사용. 보고서도
  위치·요약만 담고 원문은 사람이 직접 열람하는 전제.
- 외부 의존 0(네트워크·LLM 불필요) → 성공 기준 §8 "LLM 끊겨도 동작" 충족.

## 6. 알려진 한계 / 후속 (제안서 §6·§7·§D, 의도된 축소)

| 항목 | 현재 | 올릴 때 |
|---|---|---|
| 유사도 | `difflib` 쌍대 비교, O(n) | artifact가 ~1만 넘으면 MinHash/LSH(`datasketch`) |
| 변형 웜 | 문장 바꿔쓰기는 탐지율 낮음 | 임베딩(`sentence-transformers`) 보완, 평가로 확인 |
| 수집기 | 데모에서 `os_event` 주입 | Sysmon(ID 1·3·11·13)·ETW 실시간 구독 |
| 세션 캐시 | 읽기 이력 메모리 보관 | 장수명 세션은 이벤트에서 재구성 |
| 조회 | 라이브러리 API | 읽기 전용 MCP 서버 + 웹 대시보드 |
| 스크립트 검사 | 정규식 규칙 | YARA·Defender·VirusTotal 해시 |

코드 안의 `ponytail:` 주석이 각 축소의 상한과 업그레이드 경로를 표시합니다.
